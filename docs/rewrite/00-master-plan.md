# FCC rewrite master plan

## Objective

Rewrite the Python service into a single statically compiled, high-throughput
Go binary without changing any externally observable behavior: same wire
protocols, same provider contracts, same recovery semantics, same admin UI,
same launchers. Python remains the executable specification throughout; Go
proves conformance against golden data generated from Python at every phase.

## Ground rules

1. **No big bang.** The strangler pattern keeps a shippable product after
   every phase. Python and Go coexist behind feature flags until a subsystem
   reaches golden parity and soak time.
2. **Golden data, not re-derivation.** Each ported subsystem gets fixtures
   generated by the Python reference (`bench_local/generate_golden.py`),
   covering the happy path, every CR/CRLF/LF framing variant, malformed
   input, failure events, and edge Unicode. Go tests fail on any drift.
3. **Performance gates, measured.** Every phase ships a paired benchmark on
   shared fixtures and must not regress the recorded numbers. Current hot
   path: Go 5.4 ms vs Python 83.1 ms per 2,005-frame request (15.4x).
4. **Memory stays flat.** Bounded caches only; benchmarks report both
   allocation churn and live heap after GC. No per-stream unbounded growth.
5. **Numbers stay exact.** `json.Number` end to end. No float round-trip on
   any payload that feeds hashing, ledgers, or canonical serialization.
6. **Default-to-unsafe.** Unrecognized events mark the response unsafe for
   handoff rather than being optimistically accepted.
7. **UI is polished, not templated.** The admin UI keeps hand-written
   vanilla HTML/CSS/JS; Go serves the existing files and only the data
   contracts move. No component framework, no generated-looking markup.

## Current codebase inventory

- 423 Python modules, ~75,000 lines of application code.
- 446 test modules, ~149,000 lines of tests (9,794 tests, 10 skips).
- Subsystems by size: providers (22.1k LOC), core (14.5k), messaging (9.1k),
  runtime (7.6k), config (5.4k), application (5.1k), api (5.0k), cli (4.1k),
  harnesses (2.6k).
- 61 provider integrations, 12 agent launchers, SQLite persistence,
  Telegram/Discord bridges, admin web UI, desktop tray, optional local
  voice (torch/whisper).

## Phases, exits, and gates

### Phase 1 — Hot-path core (COMPLETE)

`sse`, `retention` with full golden parity and paired benchmarks.
Exit: all Go parity tests green; Python suite 9,794 green; 15.4x measured.

### Phase 2 — Delivery state machines (COMPLETE)

Ports the per-request decision logic that turns raw frames into delivery
evidence: `assess_recovery`, the messages-wire `DeliveredResponse`
(observation, retention limiting, snapshots, handoff eligibility, closing
and handoff events), and `ToolCallBuffer` (withhold/flush/discard and
responses-snapshot filtering).

Golden coverage: multi-block streams (text, thinking, tool_use), redacted
and opaque reasoning, missing-block and unknown-event unsafe reasons, the
1 MiB retention limit exercised at a small injected threshold, unterminated
blocks, failure-frame discard groups, responses snapshot filtering, and
every assess_recovery branch (15 cases).
Exit met: Go state output equals Python snapshots event-by-event across
`testdata/golden_phase2.json`; no Python behavior changed; the paired
benchmark now covers the full state pipeline — Go ~6.5 ms vs Python
~95-100 ms per 2,005-frame request (~15x), ~350 KiB live heap.
Remaining follow-up: responses- and gemini-wire branches of `Delivered`
(currently explicit default-to-unsafe stubs) and the tiktoken estimator
(Go ships the documented len/4 fallback behind a tokenizer interface).

### Phase 3 — Continuation and recovery streams

`ContinuationStream`, `ContinuationOverlap`, synthetic boundary events,
attempt revision handling, and the replacement-envelope identifier
rewrites. UUID generation gets an injectable factory so golden sequences
are deterministic. Exit: overlap and handoff scenarios from the Python
recovery tests replay identically in Go.

Exit met: the Go `continuation/` package replays 115 overlap scenarios
(messages, responses and gemini wires; prefix corrections, terminal
snapshots, thought exclusion, retention failures with exact 502 messages)
and 12 stream scenarios (overlap removal, handoff passthrough on all three
wires, restart namespace rotation, no-progress and native-contract
failures, boundary synthesis, prefix-item/usage merge). The `wireuuid`
package supplies RFC 4122 v4/v5 on stdlib crypto with deterministic
namespace injection; `wirejson` centralizes the simplejson-exact encoder
shared by retention sizing and token estimates. A 260-frame continuation
runs in ~0.43 ms in Go vs ~4.0 ms in Python (~9x), race detector clean.
The responses/gemini branches of `Delivered` are no longer stubs: 10
golden delivery scenarios lock item/part/text observation, unsafe reasons,
closing events and usage. Admission-layer annotation blocking remains a
phase-4 provider-adapter concern.

### Phase 4 — Transport and provider adapters

Go upstream HTTP client with the same timeout/retry/admission behavior,
then providers in traffic order: the OpenAI-compatible family first
(covers the majority of the 61 catalog entries), Anthropic-native and
Responses-API mappers next, Gemini and the long tail last. Each adapter
ships recorded request/response fixtures. The Go process exposes the frame
pipeline over a local Unix-socket RPC; Python delegates per request behind
a flag with instant fallback.

Step 4a (complete): `providerpolicy/` ports the provider failure decision
core — retry qualification for opening and streaming paths, transient
status/overload inference from statuses, bodies and prose markers,
authentication discrimination, context-window recognition, and the
canonical failure classifier with stable customer wording. httpx/openai
exception hierarchies become reconstructable data descriptors (the
installed httpx MRO makes RemoteProtocolError a ProtocolError rather than
a NetworkError, which the fixture locks explicitly). 66 failure cases plus
context-window terminal events replay identically in Go; race detector
clean.

Step 4b (complete): diagnostics parity — credential redaction, upstream
body extraction/capping, and the full `format_execution_failure_message`
envelope. RE2 lacks backreferences/lookarounds, so redaction combines a
key-prefix regex with manual value scanning and quote pairing; an
order-preserving JSON object type (`ordered.go`) keeps body key order
byte-identical to Python's `json.dumps`, with compact, non-HTML-escaped
encoding. Descriptors carry cause chains and attached streamed bodies
through RawMessage reconstruction; `ProviderErrorMessage` now redacts like
`safe_exception_message`. 18 redaction cases, one 20k-byte cap case, and
11 full envelope cases replay identically; race/vet/gofmt clean and the
phase 4a suite stays green.

Step 4c-1 (complete): admission limits and capacity. A new `admission/`
package ports `ProviderAdmissionLimits` validation (exact error wording)
and the decision core of `ProviderCapacityLimiter`: sliding-window
eviction, last-discarded readiness floor, rate-bucket timer and occupancy
verdict exposed as Evaluate/Commit/Release/Reconfigure under an injectable
clock. A virtual-clock harness drives the real asyncio limiter in the
golden generator; 13 validation cases and five scenarios replay in Go.

Step 4c-2 (complete): retry timing. `RetryConfig` validation/defaults,
capped exponential Delay with scripted jitter draws, Retry-After parsing
(numeric delta plus HTTP date, including the Python "-0000" naive-UTC
branch via an RFC1123Z fallback), exception status precedence and the
failure-label wording matrix, all golden-driven against the live
controller with a frozen clock.

Step 4c-3a (complete): the `ProviderExecution` budget state machine in
`admission/execution.go` — attempt claims with the reference's exact
guard errors, terminal succeed/fail/abandon transitions and idempotency,
record-failure-while-active semantics, attempt-remaining math, UUID4
identity and the termination hook contract (including the subtle
`_close_attempt(None)` None==None re-fire and stale-claim no-op). Nine
scenarios, 45 golden steps, replay identically; a latent non-canonical
`wireuuid.String` layout was found and fixed to 8-4-4-4-12 with its own
parity tests.

Step 4c-3b (complete): the recovery episode decision core in
`admission/controller.go` — gate permits, episode open/probe/coalesce/
exhaust transitions, leader election and waiter sets, terminal
episodes that fail every waiter, idle maintenance with immediate
self-expiry of leaderless, waiterless, probe-inactive episodes, and
the closed/terminal gate errors. Blocking sleeps and event wakes are
explicitly deferred to the transport slice (`ErrGateWouldWait`); every
mutating call, including probe arming and waiter registration, is an
explicit golden op. Nine scenarios and 32 steps replay identically
under a virtual clock with scripted jitter.

Step 4c-3c (complete): the blocking transport and attempt lifecycle in
`admission/capacity.go`, `admission/controller.go` and `admission/attempt.go`
— clock-injected capacity with wake-channel parking (occupancy waits
event-free, rate waits deadline-driven, context cancel leaves without
charging), `OpenAttempt`'s pre-loop guards matching the reference strings,
probe-permit invalidation and retry on lost races, the `Attempt`
accept/fail/correct/close lifecycle with exactly-once release, override
handling that records the original error while classifying the canonical
replacement, and the generic `RunCall` retry loop. Seven scenarios and 38
explicit golden steps (`golden_attempt4c3c.json`, virtual clock shared
with the Go replay) drive the real asyncio controller; six dedicated
race-tested concurrency tests cover the parking/wake paths the fixture
deliberately never triggers.

### Phase 5 — Catalog, config, and storage

Provider catalog and settings move as data-driven tables. SQLite schemas
and migrations port with the pure-Go driver; migration tests run against
both stacks on the same database files. Exit: a database written by Python
opens and migrates in Go and vice versa.

### Phase 6 — Service surface and admin UI

HTTP server, admin API, and the static admin UI move behind the Go binary
serving the existing hand-written assets unchanged. API contract tests run
against both servers from the same OpenAPI-shaped golden request set.
Single-binary distribution replaces the uv/Python 3.14 install.

### Phase 7 — Edges and launchers

Agent launchers become thin wrappers around the binary; Telegram and
Discord bridges port to maintained Go libraries; desktop tray and native
dialogs move last. Local voice transcription (torch/whisper) stays an
optional Python sidecar over IPC — no equivalent Go ecosystem exists, and
it is off the hot path.

## Testing strategy

- **Golden parity tests** (Go, in-tree): deterministic fixtures committed
  under `gocore/testdata`, regenerated from Python on every reference
  change.
- **Property tests**: randomized frame chunking and event ordering, with
  fast-path vs general-scanner equivalence (the pattern already proven in
  `sse`).
- **Behavioral suite stays in Python**: the 9,794 tests continue to define
  product behavior and guard the Python fallback path.
- **Migration tests**: shared SQLite files, recorded provider fixtures, and
  admin API request sets run against both implementations.
- **Soak/load**: long-running stream fan-out measuring live heap, GC pauses,
  and goroutine counts before each phase's flag flips to default-on.

## Performance and resource budget

| Layer | Budget |
| --- | --- |
| Frame pipeline per 2k-frame request | under 10 ms CPU (measured 5.4 ms) |
| Live heap per active stream | under 512 KiB steady state (measured 348 KiB) |
| Payload cache | FIFO, 64 entries, never grows with stream length |
| Retention | 1 MiB estimated budget, conservative (triggers early, never late) |
| Binary | single static file, no runtime dependency, cgo-free |

## Risks and mitigations

- **Semantic drift across 61 providers** → recorded fixtures per provider
  and Python-as-spec golden generation; adapters cannot self-certify.
- **State-machine divergence (recovery/handoff)** → event-by-event snapshot
  parity, including failure injection at every stream position.
- **Go's type system vs Python's dynamic dicts** → explicit event kinds,
  narrow typed accessors, default-unsafe fallbacks, and parity tests on
  malformed payloads.
- **Migration length** → every phase independently shippable behind a flag;
  Python remains supported until phase 7 completes.
- **Toolchain availability** → the Go bootstrap chain is documented and
  reproducible from GitHub source; the project stays stdlib-only so no
  module proxy dependency is introduced.
